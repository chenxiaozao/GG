# 推荐实现与可复现验证

当前规则版本：rules-2026-11-05。

## 实现范围

RecommendationEngine 是共享的需求和证据模块；AdvisorController 负责推荐接口编排，ApiController 保留其他业务。表单和自然语言都先做上架、库存、预算、类别、必要功能、最低续航筛选。表单必须主动选择才能允许最多20%超预算；对话须明确允许。缺少必要功能参数不是满足要求。

当前结构化功能：自动集尘、避障、防缠绕、拖地、编程、遥控；依据参数 JSON 的键值，而不是品牌/型号猜测。明确的否定值不算具备功能。未知“必须”要求、无法解析的明确预算返回澄清/无合格结果，不假装完成全面语义理解。预算支持数字、千、万、元以内及预算改为；并非覆盖所有中文数字、否定、复杂逻辑及上下文表达。

排名先按未封顶原始分排序，再展示整数规则分；不用演示销量/评分加分。续航比较仅限同类目录数据，售后加分只代表目录信息完整，不是综合性能/真实售后质量保证。无适合商品时不擅自放宽条件。

DeepSeek 在规则合格集合里检索最多40项候选。返回的编号必须来自候选集，非法编号会拦截；参数依据随响应展示。模型正文仍不能保证没有事实错误，不把“卡片已校验”说成“每句话均已证明”。

## 验证方法

运行 mvn test。RecommendationEngineTests 使用 recommendation-cases.json 中12条人工构造约束题与6条虚构商品测试预算、放宽、类别、缺货、下架、必要功能、否定、缺字段、续航及未知要求。另有双入口一致性、追问更新预算和排序证据检查。

结果生成到 target/recommendation-evaluation.json。该报告是可重复的软件约束测试，不是用户实验、市场参数真实性证明或大模型效果对照实验。不得把通过率改写成用户满意度或论文中的推荐准确率。真实模型基线、盲评和用户研究需要实际执行后再写结论。

## 后续扩展方式

新增必要功能须同时添加参数证据词、否定用例、跨入口用例和界面选项；不要只在提示词里宣称支持。扩展尺寸/接口等数值约束时需统一单位与缺失值语义。真实用户提问与商品参数变化应经过脱敏、版本化，再加入回归集。
